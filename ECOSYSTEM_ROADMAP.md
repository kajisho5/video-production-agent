# Roadmap — video-production-agent

Part of the [AI Video Production OS](https://github.com/kajisho5/AI-video-production-OS/blob/main/docs/ecosystem/ROADMAP.md) ecosystem: department **司令塔 (Command)**, status `active`.
Written from a read-only audit of this repository on 2026-10-30. Each step below is meant to be one pull request; tick it off by linking the PR.

## Where it stands

Python orchestrator (`video-agent`). 10 adapters (ffmpeg-skill, video-editing, audio-production, color-grading, motion-graphics, subtitle, thumbnail, qc, media-analysis, transcription). Brain: deterministic rules + optional AI (Claude API, ADR-049; the chat model through MCP, ADR-050). Handoffs for steps no installed skill can run (ADR-051). 405 unit + 53 integration tests.

## What this repository owns

`ecosystem.json` gives each job to exactly one repository. Work outside this list belongs to its owner and is handed over, not re-implemented.

| Owned job | Status | Note |
|---|---|---|
| 制作計画 | done | plan / revise / approve / render |
| スキルの呼び分け | partial | every ecosystem job has a SkillSpec, so a handoff names its package (ADR-057); 17 of them have no adapter yet (step 9) |
| 制作記録(ProductionReceipt) | done | ADR-040 |

## Wiring

Uses 17 of ffmpeg-skill's 42 tools directly through a hand-maintained catalog (19 entries; fit, report unreachable; scenes for `--beats` only, ADR-053). Reads ffmpeg-skill's `_contract.py --json --static` and `doctor --json` at locate time to check the catalog (ADR-056). NLE interchange (OTIO / FCPXML / EDL) through ffmpeg-skill `render --export-timeline` (ADR-052). qc-skill pinned at 0.2.3; its opt-in VMAF / SSIM / PSNR against a master the user names (`qc.reference_video` + `qc.reference_metrics`, ADR-058, [#77](https://github.com/kajisho5/video-production-agent/pull/77)).

Allowed keys are derived from the `--set` validator (`service.BRIEF_REQUIREMENT_KEYS`: switch / refinement keys + `delivery.timeline`, without policy / approval, file-path, `job.*`, `provider.*`); every key from any reader goes through the same checks as `--set`, unknown keys and invalid values refused with the reason, explicit `--set` wins (`overridden`). Readers: the Claude provider (key enum in the JSON schema) or the chat model's answer (`--brief-requirements`, host provider); each item must quote a phrase of the brief. No provider (or a failure) = the rule-based reader, English and Japanese: duration (reported as unmapped: no key for a target length), vertical / 9:16 / 「縦」 → `edit.fit=9:16` (also 16:9, 1:1, 4:5, 4:3), captions / 「字幕」 → `subtitle` (+ burn-in, srt / vtt), `-14 LUFS` / 「ラウドネス -14」 → `audio.loudness.target_lufs` + `audio.normalize`, dBTP, the request keywords. The example yields `edit.fit=9:16`, `subtitle=true`, `audio.loudness.target_lufs=-14`, `audio.normalize=true`, with "60 s" unmapped. AI-read keys are AI_GENERATED; every change resting on them is CONFIRM, the reading is decision `requirements.brief` with the brief as evidence (rejecting it drops the keys on revise). `tests/test_brief.py`, evals 115-116
